# Төслүүдийн дэлгэрэнгүй

**Сүүлд шинэчилсэн:** 2026-08-06

> Энэ файл нь төсөл тус бүрийн **context** — зорилго, оролцогч тал, шийдвэр, эрсдэл.
> Таскийн **төлөв** энд байхгүй — [`taskuudiin-burtgel.md`](./taskuudiin-burtgel.md)-ээс үзнэ үү.

---

## 1. УВС аймгийн төсөл (`UVS`)

- **Төлөв:** Үргэлжилж буй, гэрээт ажил
- **Зорилго:** Эхэлсэн үе шатыг төлөвлөгөөт хугацаанд хүлээлгэн өгч, дараагийн үе шат руу шилжих
- **Гол эрсдэл:** Орон нутгийн ажил тул логистик, командировкийн хуваарь нөөцөд шууд нөлөөлнө
- **Дараагийн 3 алхам:** явцын үнэлгээ (UVS-01) → дараагийн үе шатын хуваарь батлуулах (UVS-02) → акт + нэхэмжлэх (UVS-04)
- **Тодруулах:** Гэрээний хамрах хүрээ, үе шатны хуваарь, нэхэмжлэлийн одоогийн байдал

## 2. Хөвсгөл аймгийн төсөл (`KHU`)

- **Төлөв:** Үргэлжилж буй, гэрээт ажил
- **Зорилго:** Явцын ил тод байдлыг сэргээж, үлдсэн ажлыг хуваарьт оруулах
- **Гол эрсдэл:** УВС-тай нөөц (инженер, тоног төхөөрөмж) хуваалцах магадлалтай — давхардвал хоёулаа хожимдоно
- **Дараагийн 3 алхам:** явцын үнэлгээ (KHU-01) → харилцагчтай уулзалт (KHU-02) → нэмэлт шаардлагыг өөрчлөлтийн хүсэлт болгох (KHU-03)
- **Тодруулах:** Аль үе шатанд явж байгаа, нээлттэй техникийн асуудал юу байна

## 3. Төрийн банк — Statebank (`SB`)

- **Төлөв:** Үргэлжилж буй
- **Зорилго:** Одоогийн үе шатыг хаах, дараагийн үе шатны хамрах хүрээг тохирох
- **Онцлог:** Банк тул зохицуулалт, дотоод хяналтын шаардлага өндөр — баримтжуулалт дутвал хүлээн авалт удаашрана
- **Дараагийн 3 алхам:** статус тодруулах (SB-01) → нэмэлт баримт бүрдүүлэх (SB-02) → нэхэмжлэхийн байдал шалгах (SB-04)
- **Тодруулах:** Банкны талын хүлээлт, шаардаж буй нэмэлт баримтын жагсаалт

## 4. Монголбанк (`MB`)

Хоёр урсгал зэрэг явна:

### 4.1 P1 — ISO хэрэгжүүлэлт

- **Зорилго:** ISO/IEC 27001-ийн шаардлагад нийцүүлэх ажлыг эхлүүлж, gap analysis-аар суурь тогтоох
- **Дараалал:** төлөвлөгөө батлуулах → gap analysis → дутуу журам → эрсдэлийн бүртгэл → дотоод аудитад бэлтгэх
- **Тэмдэглэл:** Энэ ажилд репод байгаа `compliance-audit-mn` ур чадвар (skill) шууд ашиглагдана — Annex A хяналтын мэдээлэл, тайлангийн загвар бэлэн

### 4.2 P2 — FortiNET худалдаа

- **Зорилго:** FortiNET шийдлийн техник, үнийн саналыг **14 хоногийн дотор (→ 2026-08-20)** хүргүүлэх
- **Гол хамаарал:** Дистрибьютерийн албан үнэ, нийлүүлэлтийн хугацаа — эдгээргүйгээр санал бодитой болохгүй
- **Гол эрсдэл:** Нийлүүлэлтийн хугацаа амлалтад багтахгүй байх (R4). Саналдаа хүчинтэй хугацаа, нийлүүлэлтийн нөхцөлийг тодорхой заана
- **Тэмдэглэл:** ISO болон Forti-г нэг харилцагч дээр зэрэг явуулах нь давуу тал — ISO-гийн gap analysis нь Forti-ийн техникийн үндэслэлийг бэхжүүлнэ

## 5. Tech Partner (`TP`)

- **Зорилго:** (а) FortiNET-ийн албан ёсны партнёр болох, (б) MobiNET-тэй хамтын ажиллагааны боломжийг тодруулах
- **Яагаад чухал:** Партнёрын статус нь Монголбанк болон бусад Forti-ийн худалдаанд үнийн давуу тал, техникийн дэмжлэг өгнө — өөрөөр хэлбэл `MB-05`-ийн ашигт ажиллагаанд шууд нөлөөлнө
- **Дараалал:** түвшин тодруулах → материал бүрдүүлэх → инженерийн NSE сертификац
- **MobiNET:** Уулзалтад орохоос өмнө хамтын ажиллагааны 2–3 тодорхой хувилбар (дилер / хамтарсан төсөл / техникийн нөөц) бэлдсэн байх

## 6. Pentesting (`PT`)

- **Зорилго:** (а) Зандан дээрх Web pentest-ийг гүйцэтгэх, (б) "мини аудит" үйлчилгээг давтагдах бүтээгдэхүүн болгон стандартчилах
- **Хатуу дүрэм:** Бичгээр зөвшөөрөл (`PT-02`) гарын үсэг зурагдтал ямар ч тест **эхлүүлэхгүй**. Хамрах хүрээнээс гадуурх хостыг хөндөхгүй
- **Дараалал:** scope → гэрээ + зөвшөөрөл → тестийн цонх → гүйцэтгэл → тайлан → retest
- **Бизнесийн боломж:** Мини аудитыг стандартчилвал (`PT-07/08`) Монос, NOMIN, УБТЗ зэрэг шинэ харилцагчид рүү орох хямд "нэвтрэх цэг" болно

## 7. УБТЗ (`UBTZ`) — 🔥 яаралтай

- **Төлөв:** Уулзалтын өмнөх шат
- **Зорилго:** Уулзалт → гэрээ рүү хамгийн богино замаар шилжих
- **Яагаад яаралтай:** Тэмдэглэлд яаралтай гэж заасан — гэрээ байгуулах цонх хугацаатай байх магадлалтай
- **Анхаарах:** УБТЗ бол том, төрийн оролцоотой байгууллага — худалдан авалтын журам (шууд гэрээ эсэх, тендер шаардлагатай эсэх) уулзалт дээрээ шууд тодруулна. Үүнээс хамаарч гэрээний хугацаа 2 долоо хоног ч, 2 сар ч болж мэднэ
- **Дараагийн 3 алхам:** уулзалт товлох (UBTZ-01, өнөөдөр) → танилцуулга бэлтгэх (UBTZ-02) → уулзалт хийж нөхцөл тохирох (UBTZ-03)

## 8. Монос, NOMIN (`RTL`)

- **Төлөв:** Уулзалт товлох шат — эрт үе
- **Зорилго:** Хоёр том дотоодын группт үйлчилгээгээ танилцуулж, эхний ажлын боломж илрүүлэх
- **Хандлага:** Ерөнхий танилцуулга биш — салбарын онцлогт тохирсон өнцөг:
  - **Монос:** эрүүл мэнд/эмийн салбар → хувь хүний эмзэг мэдээлэл хамгаалах, эмийн сангийн систем, цахим худалдааны платформын аюулгүй байдал
  - **NOMIN:** ретайл/ложистик → төлбөрийн систем, POS, нийлүүлэлтийн сүлжээний эрсдэл
- **Эхний санал болгох бүтээгдэхүүн:** мини аудит (`PT-07`) — бага өртөгтэй, хурдан үр дүнтэй

## 9. Summit — авлага (`SUM`)

- **Төлөв:** Төлбөрийн авлагатай
- **Зорилго:** Авлагыг барагдуулах, эсвэл бодитой төлбөрийн хуваарь тохирох
- **Дараалал:** дүн баримтжуулах → тооцоо нийлэх акт + албан шаардлага → төлбөрийн хуваарь → шаардлагатай бол эрх зүйн алхам
- **Дүрэм:** Авлага барагдтал Summit-д шинэ ажил эхлүүлэхгүй (`SUM-05`) — эс тэгвэл авлага өснө
- **Тодруулах:** Авлагын дүн, хугацаа хэтэрсэн хоног, гэрээнд торгуулийн заалт байгаа эсэх

## 10. МУХБ консалтинг (`MUHB`)

- **Төлөв:** 🔴 Techdata-тай холбоотой хүндрэлээр гацсан
- **Зорилго:** Гацааг арилгах, эсвэл нөөц хувилбараар хүргэлтээ үргэлжлүүлэх
- **Гол зарчим:** Гацаа арилахыг хүлээж суухгүй — **эскалаци (MUHB-02) ба нөөц хувилбар (MUHB-03)-ыг зэрэг явуулна**
- **Харилцагчийн харилцаа:** МУХБ-д нөхцөл байдлыг эрт мэдэгдэнэ (`MUHB-04`). Хугацаа хэтэрсний дараа мэдэгдэх нь итгэлийг алдагдуулна
- **Тодруулах:** Хүндрэл нь яг юу вэ — нийлүүлэлтийн хугацаа, үнэ, лиценз, эсвэл техникийн нийцэл үү?

## 11. АШИУС (`ASH`)

- **Төлөв:** Худалдан авалтын шатанд
- **Зорилго:** Худалдан авалтын шаардлагад бүрэн нийцсэн санал хугацаанд нь хүргүүлэх
- **Хамгийн эрсдэлтэй цэг:** Эцсийн хугацаа (`ASH-04`) — үүнийг эхний ээлжид баталгаажуулна. Хугацаа алдвал бусад бүх ажил үрэгдэнэ
- **Дараагийн 3 алхам:** шат/хугацаа тодруулах (ASH-01) → ТТ-ийн нийцлийг шалгах (ASH-02) → материал бүрдүүлэх (ASH-03)

## Тодруулах асуултууд

Эдгээр хариу тодрох хүртэл холбогдох таскууд таамаглал дээр суурилж байна:

| # | Асуулт | Нөлөөлөх таск | Яагаад чухал |
|---|---|---|---|
| 1 | **"МВ"** нь Монголбанк мөн үү, эсвэл өөр байгууллага уу? | Бүх `MB-*` | Хэрэв өөр бол тусад нь төсөл болгож, 14 хоногийн хугацааг зөв харилцагчид хамааруулна |
| 2 | "Тоон тэмдэглэлүүд" гэдэг нь юу вэ (үнийн дүн, тоо хэмжээ, KPI)? | `MB-08` | Хэмжигдэхүйц зорилт болгож бүртгэхэд шаардлагатай |
| 3 | Таск бүрийн **эзэн** хэн бэ? | Бүх | Эзэнгүй таск гүйцэтгэгддэггүй. Даваа гарагт нөхнө |
| 4 | Summit-ийн авлагын дүн, хугацаа хэтэрсэн хоног? | `SUM-01…05` | Барагдуулалтын арга (зөөлөн сануулга vs эрх зүйн алхам) үүнээс хамаарна |
| 5 | УБТЗ-ийн уулзалтын шийдвэр гаргагч хэн бэ? | `UBTZ-01` | Буруу түвшний хүнтэй уулзвал гэрээ рүү шилжихгүй |
| 6 | Зандан — Web pentest-ийн хамрах хүрээ (домэйн, орчин, тестийн төрөл)? | `PT-01…05` | Хугацаа, үнэ, багийн ачаалал бүгд үүнээс хамаарна |
| 7 | АШИУС-ын саналын эцсийн хугацаа хэзээ вэ? | `ASH-04` | Хамгийн өндөр эрсдэлтэй огноо |
| 8 | МУХБ дээрх Techdata-ийн хүндрэлийн мөн чанар? | `MUHB-01…03` | Гацааг арилгах арга үүнээс хамаарна |
| 9 | УВС, Хөвсгөл, Statebank төслүүдийн одоогийн үе шат, гэрээт хугацаа? | `UVS-*`, `KHU-*`, `SB-*` | Одоогоор ерөнхий загвар таск тавьсан — бодит хуваарьтай тулгах шаардлагатай |
